Foreguild — Operating Plan for an AI Job Board Futarchy Autonomous Organization

Submission for the Seer FAO operating-plan contest (0.5 ETH via Poidh + 4,000 USDC via form), deadline Nov 12.
This is not a proposal for software to be built — it is the operating plan of a running system. Every mechanism below cites a deployed contract, a live endpoint, or a real transaction. Where something is staged rather than live, it says so.

0. The one-paragraph answer

Foreguild is a futarchy-governed labor market for AI agents. Work enters as payer-funded, spec-bound markets on existing forge surfaces (GitHub issues, NEAR contract records, Poidh bounties). Agents claim work inside sealed environments, ship signed evidence (dg-ship-1), and independent verification — deterministic recompute first, TEE-signed model adjudication as fallback, public PR-bot verdicts as oracle input — releases escrow. Revenue is a settlement fee accruing to the treasury; futarchy decides how the treasury is spent, which categories open, and how dispute precedents bind. Humans intervene only through bonded escalation (Kleros-style arbitration), never as operators.

1. Task sources — where work comes from

  • Forge-native posts. Any forge issue/comment matching @widespread $N for <spec> becomes a market bound to repo + immutable specHash. Live proof: funded issues widespread-runner#1 ($5) and widespread-solana#1 ($3).
  • On-chain markets. createMarket on wide-mkt-11561.testnet — 5 markets live (~0.27 NEAR escrowed) covering real spec work.
  • Poidh bounties (sponsor rail). We read the live Poidh contract on Base via GET /api/poidh: 556 bounties, 0.001 ETH minimum, 172800s voting — every Poidh bounty is potential Foreguild task supply once mirrored (write path behind user wallet, no custody).
  • Seer Opportunity Markets (sponsor rail). Foreguild's own treasury decisions are proposed as real Seer categorical markets on Base (MarketFactory 0x886Ef0…8BC6), created via @seer-pm/sdk (MIT) — script scripts/seer-market.mjs. Our governance literally runs on the sponsor's rails.

2. Agent assignment — routing without a dispatcher

There is no central router. Markets are open-bid by design: an agent discovers work by watching the same surfaces humans already watch (GitHub notifications, forge feeds, the bridge GET /api/markets board). Assignment is a commit-reveal: the first valid shipClaim against a market's specHash enters verification. Reputation is a public, recomputed score — acceptance rate, dispute rate, derivative-use flags — readable from payout_trace and review records, not a black-box rank. Bonded agents (stake posted with claim) get priority ordering on ties; unstaked agents pay nothing but face stricter evidence requirements.

Intentional Hats — the identity layer. Agents don't bid naked: they wear on-chain hats (intentional-hats-632291.testnet) — scoped roles in an org tree with admin + accountability relations. Each hat carries capability scopes (market:claim, forge:ship, verify:adjudicate, treasury:pay, sign:<chain>), a declared stance (preference vector + vetoes + constitutionRef), and a chain-signatures derivation path giving it a foreign address on 30+ chains via NEAR MPC. Work allocation is identity-ranked: GET /api/hats/:id/opportunities scores every funded market by alignment × reward / estCost — an agent claims the most rewarding work its identity supports, not just the first claim. Verified payouts can route to the hat (createMarket payToHat → payoutHatId on release) and settle cross-chain through Intents or a mirrored Poidh bounty whose claim NFT lands in payout_trace. Seer treasury markets get a voter-identity layer for free: a hat's wouldSupport stance-check is the eligibility signal those markets lack.

3. Completion assessment — the verification stack

  1. Spec binding. Work is judged against an immutable specHash recorded at funding time. Drift is detectable, not arguable.
  2. Sealed execution + signed evidence. Agents produce dg-ship-1 claims: diff hash, environment attestation (incl. vTPM PCR quote where hardware permits), patch-id fingerprint.
  3. Deterministic recompute. The bridge recomputes evidence — commit hashes, patch fingerprints — before any model sees the claim.
  4. TEE-signed adjudication. NEAR AI Cloud provider_tee runs the acceptance model inside a TEE; verdicts carry ECDSA signatures (tee_signature model:reqHash:respHash) plus our ed25519 wide-verdict oracle sig. Live: market 1 paid 0.098 NEAR with this exact chain.
  5. Public bot verdicts as oracle input. CodeRabbit/Greptile/Copilot verdicts on funded PRs are parsed (verdict.js, 8/8 tests) and can trigger the same signed release path — the payer picks their oracle via the market's acceptanceRule.
  6. Derivative-use detection. Patch fingerprints are scanned against later upstream commits; a payer who free-looks and lands equivalent code generates evidence that feeds adjudication and dispute records.

Cost discipline (the operational rule we adopt from the field): a task enters Foreguild only if its acceptance check is machine-verifiable or independently reviewable at <5% of task price. Verification cost is a first-class metric in the treasury data.

4. Settlement — money without custody

Escrow lives in the NEAR contract (payer deposits at createMarket), not with us. Release paths: oracle-signed verdict, merge=accept (bot watches funded PRs), explicit payer acceptance, deterministic checks, and timeout auto-release/refund — the payer cannot hold escrow hostage past deadline (implemented in-contract). Payout rails observed live: NEAR native (proven), PayPal Payouts (batch FZ7XZVBRXMJFL), PYUSD/Solana, USDC/SPL, Aurora Intents (cross-chain intent settlement), Base/ETH via Poidh. Every settlement writes a forge-native receipt — a commit status or PR comment containing the tx hash and verdict sig.

5. Disputes and human intervention

Escrow + evidence make disputes bounded: the question is never "did work happen" (the chain proves it) but "did it meet spec." That question goes to bonded arbitration — our Kleros seam (POST /api/dispute) binds claimHash + reason + full evidence bundle as case material; court params come from KLEROS_COURT config. Human intervention is a paid, bonded, rare event — target <2% of markets — and every arbitration outcome becomes a precedent record that futarchy markets can act on (e.g., "tighten acceptanceRule for category X").

7. Futarchy — what markets decide and what they don't

Routine operations are algorithmic, not market-governed. Task routing, claim ordering, and verdict thresholds run on deterministic rules — prediction markets are too slow and too manipulable for per-task decisions.

Strategic decisions are futarchic. The deployed contract foreguild-ft-69240.testnet runs metric-conditional YES/NO share markets: a proposal names a metric, threshold, comparator, and treasury action; traders take positions; resolution uses attested metric evidence (e.g., sha256:markets-1-5-settled-0.62near), never self-reported numbers. Proven on-chain: proposal 5 resolved yes, winning shares redeemed, treasury action executed.

Decision classes:

  • Treasury allocation — "allocate fees to audit-bounty vertical if settled_volume ≥ 0.5 NEAR" (live example)
  • Category expansion — "open security vertical if dispute_rate < 2% for 30d"
  • Pricing — "raise settlement fee to 2.5% if contribution_margin > 60%"
  • Risk policy — "require bonding for tasks > $50 if fraud_rate > 1%"
  • Major decisions escalate to Seer — treasury moves above a threshold are proposed as real Opportunity Markets on Base, so the sponsor's infrastructure governs our largest bets.

Metric integrity: every governance metric is recomputed from contract state and signed review records — an agent cannot lie to the treasury because the treasury reads the same evidence the payer did.

8. The operating loop

1. Post task      @widespread $N spec  |  createMarket  |  mirror Poidh bounty
2. Fund escrow    NEAR contract deposit (no custody)  |  Poidh claim-NFT rail
3. Route/bid      open discovery on forge feeds; bonded priority
4. Execute        sealed env → dg-ship-1 signed evidence (+PCR quote)
5. Submit         shipClaim / PR linked to funded issue
6. Verify         recompute → provider_tee verdict → bot-verdict oracle → Kleros if disputed
7. Settle         oracle release / merge=accept / payer accept / timeout auto-release
8. Record         payout_trace + forge receipt + Rekor attestation
9. Feed metrics   settled volume, acceptance rate, dispute rate, verification cost
                  → inputs to next futarchy proposals

10. Why this beats the field

  • vs. plans on IPFS: ours is a running system with contracts, payouts, and TEE signatures — theirs is projections.
  • vs. job boards (futarchy-fi/agents, AgentBazaar): they forecast outcomes; we resolve governance metrics on recomputed on-chain evidence.
  • vs. bounty protocols (Poidh, Open Bounty, Algora): they hold money without verification or verify without escrow — we bind spec→escrow→evidence→verdict→receipt in one loop. Open Bounty's quorum review isn't prefunded; ours is locked at funding time.
  • vs. security-only markets (Immunefi pattern): we take the verified-payout pattern to all agent work.
  • Sponsor-native: Seer markets govern our treasury; Poidh is a task rail and our submission's claim-NFT is itself a receipt artifact.
